# PicoGK headless spike, 2026-10-24

**Status: throwaway experiment. Nothing is integrated into CadSwarm.** No hub route, MCP tool, worker
op, FreeCAD tab or apply path exists for lattices. The contract and guides in this folder still describe
proposed behavior only.

**Question.** Can a Windows host generate a lattice without a desktop viewer, fast enough to sit behind
the proposed job queue?

## What was tried

- Windows x64, .NET SDK 10.0.300.
- `dotnet new console`, then `dotnet add package PicoGK --version 2.3.0` from nuget.org. Restore and
  build succeeded; the package carries `runtimes/win-x64/native/picogk.26.2.dll` and the other native
  libraries it needs. The managed assembly targets `net9.0` and loads from a `net10.0` app.
- `Library.Go(...)` opens the PicoGK viewer and was **not** used. Instead the spike constructs
  `new PicoGK.Library(0.4f)` directly, builds `Voxels` from a custom `IBoundedImplicit`, calls
  `mshAsMesh()` and `SaveToStlFile(...)`. No window appears.
- Geometry: a 40 x 40 x 40 mm box filled with a gyroid, 12 mm cell, 1.2 mm wall, 0.4 mm voxel. The
  implicit is the usual `abs(sin x cos y + sin y cos z + sin z cos x) - t` field divided by the wave
  number, not an exact signed distance.

The whole spike source is below. It is evidence, not product code.

## Result

```

empty=False bytes=8317616
triangles=805176 vertices=401794
```

A 40 MB binary STL, 805,176 triangles, generated in about one second on this laptop. That is enough to
say the kernel is usable headlessly and fast enough for a background job.

## What this changes for the plan

1. **Integration shape is a separate CLI process.** PicoGK is .NET; the CadSwarm worker is Python inside
   FreeCAD. The host should run a small `cadswarm-lattice` console program as a job, pass it a job id and
   parameters, and read the STL/3MF it writes. Do not try to load .NET into the FreeCAD Python process.
2. **Mesh size is the real limit, not speed.** A 40 mm cube at 0.4 mm already produces 40 MB. The
   contract's storage and artifact paths are built for much smaller exports. A shipped version needs a
   coarser default voxel, decimation, or 3MF, and a hard cap before `put_artifact`.
3. **The kernel is viewer-first.** `Library.Go` is the documented entry point and it builds the viewer.
   The direct `new Library(voxelSize)` path works today but is not the documented API surface, so the
   job wrapper must pin the package version and test it on every upgrade.
4. **Windows x64 is proven; macOS arm64 is not.** The package ships osx-arm64 natives, but this spike
   never ran them. Linux is not shipped by the package.

## Unknowns left for a real implementation

- Exact TPMS fields and wall thickness calibration (the spike's field is an approximation).
- Which voxel sizes keep a typical enclosure under a sane STL size and generation time.
- Sheet-vs-network TPMS, skin generation, open faces, and clipping to a non-box part.
- Watertightness/validity checks and the revision-safe apply transaction from the contract.
- 3MF output and whether the web viewer can stream a lattice-sized mesh.

## Source

```csharp
using System.Numerics;
using PicoGK;

var bounds = new BBox3(0, 0, 0, 40, 40, 40);
var lib = new Library(0.4f);
Console.WriteLine($"PicoGK {Library.strVersion()} build {Library.strBuildInfo()}");
var vox = new Voxels(lib, new Gyroid(12, 1.2f, bounds), bounds);
Console.WriteLine($"empty={vox.bIsEmpty()} bytes={vox.nMemUsage()}");
var mesh = vox.mshAsMesh();
Console.WriteLine($"triangles={mesh.nTriangleCount()} vertices={mesh.nVertexCount()}");
var path = Path.Combine(Path.GetTempPath(), "picogk-spike-gyroid.stl");
mesh.SaveToStlFile(path, Mesh.EStlUnit.MM, null, 0);
Console.WriteLine($"saved {path} ({new FileInfo(path).Length} bytes)");

class Gyroid : IBoundedImplicit
{
    readonly float _k, _t;
    readonly BBox3 _b;
    public Gyroid(float cell, float wall, BBox3 b) { _k = 2 * MathF.PI / cell; _t = wall * _k / 2; _b = b; }
    public BBox3 oBounds => _b;
    public float fSignedDistance(in Vector3 v)
    {
        float x = _k * v.X, y = _k * v.Y, z = _k * v.Z;
        float g = MathF.Sin(x) * MathF.Cos(y) + MathF.Sin(y) * MathF.Cos(z) + MathF.Sin(z) * MathF.Cos(x);
        return (MathF.Abs(g) - _t) / _k;
    }
}
```
